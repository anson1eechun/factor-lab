# 修正案 A1 — 執行價壞點過濾(decimal-scale corruption)

## 1. 發現

Phase 2 首跑產出的**美元層**數字自相矛盾:G5(i) 殘差版 `ann_return = 5.50`(550%/年)
卻只有 `sharpe = 0.46`;G4 的五分位淨報酬為 `[0.00089, 0.00041, 0.01494, 0.01415, 0.00170]`
——**中間分位**報酬是兩端的 10 倍以上。排序層(Spearman Rank IC)數字則完全正常。
IC 與 P&L 的這種脫鉤指向少數極端報酬值,而非訊號性質。

追查結果:執行價面板 `px0015` 有**十進位尺度壞點**。

| coin-day | px0015 / close(k−1) |
|---|---|
| 2026-01-28 FLOW | 1.01e-4 |
| 2026-04-16 DYDX | 9.90e-4 |
| 2026-04-22 XTZ | 1.000e-3 |
| 2026-04-22 SNX | 1.007e-3 |
| 2026-04-29 CRV | 1.004e-3 |
| 2026-04-29 GALA | 9.97e-3 |
| 2026-06-12 IOTA | 9.98e-3 |
| 2026-06-12 KAVA | 1.002e-2 |
| 2026-06-12 ROSE | 1.003e-2 |

比值**精確落在 10 的次方**上,且成群出現於同一天(2026-04-22 兩檔、2026-04-29 兩檔、
2026-06-12 三檔)。**根因在 Binance 原始逐筆資料,不在本輪的擷取程式**:
實測 `FLOWUSDT/2026-01` 檔內,2026-01-28 當日有 **15,797 筆**成交價落在 `7.3e-06`
(當日中位價 `0.07037`),trade id 連續(133,245,187 起),時間從 00:15 持續到 03:01。

單一 `R = +9245` 的報酬值即足以摧毀全部美元層統計量。**排序層 IC 因為用 Spearman 而免疫**
——這正是 IC 正常而 P&L 荒謬的原因。

## 2. 修正規則(機械化,零自由度,零前視)

> 以**嚴格先前資訊**驗證當日執行價:
> `bad(i,k) := |log( px0015(i,k) / close(i,k−1) )| > log(10)`,且 `close(i,k−1)` 可得。
> 被標記者 `px0015(i,k) := NaN`;其衍生報酬 `R(i,k−1)` 與 `R(i,k)` 隨之為 NaN,
> 依 runner 既有約定計為**該幣當日 0 報酬**(部位續抱)並計入 `n_missing_R`。

**解析度檢定(v2.4 §2 要求)**:門檻 **5x / 10x / 20x / 50x / 96x 標記出完全相同的 9 個 coin-day**。
唯一的真實極端值 `DOGE 2021-01-28`(px0015/close(k−1) = 0.203,即 2021-01-28 真實的
DOGE 暴漲日)在 5x 以上的任何門檻下**均不被標記**。真實事件(|log| = 1.59)與最輕汙染
(|log| = 4.60)之間有 **20 倍的乾淨間隙**,故「兩種同樣可辯護的口徑跨越門檻」的情形不存在,
本條款有解析度。

**零前視**:僅使用 `close(k−1)`,不使用當日或未來任何價格。真實交易者在 00:15 看到
一個偏離昨收 1000 倍的成交價,本來就不會照它成交。

## 3. 紀律處置

1. 本修正案**在裁決前**書面提出,不在看到閘門結果後選擇性套用。
2. **修正前與修正後的數字全部落盤並登錄 ledger**;修正前版本保存為
   `SIM-2026-09-14-001_results_precontam.json`。
3. 修正**不改變任何訊號規格、閘門門檻或參數**,只修 P&L 記帳所用的價格輸入。
4. 排序層(IC)數字預期幾乎不變(9 / 133,656 個 coin-day);若 IC 有實質變動,
   應視為修正案本身有問題而回頭檢討。
5. 本修正案計為**一次額外的資料處理決策**,由 Arbiter 自行決定是否計入多重比較 N。

## 4. 對本輪判讀的意義(事前聲明)

修正後若美元層仍不達 G2,則「排序層真、美元層不可收割」的判讀成立;
若修正後美元層大幅改善,則**首跑的所有美元層數字作廢**,以修正後為準,
且必須在報告中明載首跑遭汙染一事,不得只呈現修正後的漂亮版本。
